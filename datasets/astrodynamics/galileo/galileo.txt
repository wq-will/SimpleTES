Design an impulsive multiple-gravity-assist interplanetary trajectory for a
specified mission brief.

This subtask always evaluates the sibling Galileo mission instance.

This task is a mission-design benchmark, not an abstract algorithm benchmark.
For each run, the evaluator injects one selected `problem` dict describing one
named space mission: launch/capture windows, allowed flyby bodies, launcher or
boundary energy model, flyby altitude constraints, node budget, and target
delta-v. Your program is run for that mission.

Your program must define run_code() returning a list of trajectory node
dictionaries. All node types use the same field structure:

  {"type": t, "time": MJD, "planet_id": id, "r": [x,y,z],
   "v_before": [vx,vy,vz], "v_after": [vx,vy,vz]}

Node types and field semantics:
  start:  v_before = reference velocity,    v_after = spacecraft departure velocity
  end:    v_before = spacecraft arrival vel, v_after = reference velocity
  GA:     v_before = incoming heliocentric,  v_after = outgoing heliocentric
  DSM:    v_before = pre-maneuver velocity,  v_after = post-maneuver velocity
          dv = |v_after - v_before|

planet_id:
  "0" = state reference or DSM.
  "1"-"8" = Mercury, Venus, Earth, Mars, Jupiter, Saturn, Uranus, Neptune.

Units: time in MJD (UTC), r in km, v in km/s. Times must be strictly increasing.

Pre-defined bindings, do not define them yourself:

problem is preloaded from this task's instance.json and contains:
    "id": str
    "mission_name": str
    "description": str
    "mission_class": str
    "design_goal": str
    "reference_family": str
    "mu_sun": 1.32712440018e11
    "planet_mu": {"1": GM, ..., "8": GM}
    "planet_radius": {"1": R, ..., "8": R}
    "start": boundary_spec
    "end": boundary_spec
    "allowed_GA_planets": ["2","3",...]
    "flyby": {"min_altitude_km": {"2": 200, ...}}
    "max_nodes": int
    "max_GA": int
    "max_DSM": int
    "target_dv": float
    "timeout_seconds": float

Boundary specification:

  Type 1: "periapsis_maneuver" -- impulsive burn at planetary periapsis.
    {"type": "periapsis_maneuver", "planet_id": "5",
     "time": {"kind": "window", "lo": MJD, "hi": MJD},
     "h_factor": 4.0, "T_days": 270}

    dv formula:
      vinf = |v_after - v_planet|  (start)  or  |v_before - v_planet|  (end)
      r_peri = R_planet * (1 + h_factor)
      T = T_days * 86400 s
      dv = sqrt(vinf^2 + 2*mu/r_peri)
           - sqrt(2*mu/r_peri - (4*pi^2*mu^2/T^2)^(1/3))

  Type 2: "piecewise_linear" -- launcher/capture energy cost curve.
    {"type": "piecewise_linear", "planet_id": "3",
     "time": {"kind": "window", "lo": MJD, "hi": MJD},
     "breakpoints": [[vinf, dv], ...]}

    dv = piecewise_linear_interpolation(|v_after - v_before|, breakpoints)
    If planet_id == "0": time must be exact and state_r/state_v must be provided.

tools = Tools(), with these primitives:
    r, v = tools.ephem(planet_id, mjd_utc)
        Heliocentric planetary state from DE430 ephemeris.

    r, v = tools.propagate_two_body(r0, v0, tof, mu)
        Keplerian two-body propagation.

    v0, v1 = tools.lambert(r0, r1, tof, mu, *, prograde=True, lowpath=True, M=0)
        Lambert solver. Try multiple time-of-flight choices, transfer geometry
        choices, and revolution counts when useful.

    v_out = tools.gravity_assist(v_in, v_planet, mu_p, r_p, psi)
        Unpowered flyby by rotating v_inf.

    r_p, dv_flyby, feasible = tools.powered_flyby(v_arr, v_dep, v_planet, mu_p, min_r_p)
        Powered-flyby compatibility and mismatch cost for independently chosen
        incoming and outgoing Lambert arcs.

The evaluator independently verifies:
0. Runtime: each mission must finish within problem["timeout_seconds"].
1. Schema: node fields, node order, time monotonicity, and node budgets.
2. Planet positions: non-DSM planet nodes must match ephemeris.
3. Two-body propagation: adjacent nodes must match Keplerian propagation.
4. Gravity assists: powered-flyby periapsis feasibility and mismatch cost.
5. Boundary windows and boundary reference velocities.
6. Total delta-v:
      start_boundary_dv
    + sum(powered-flyby mismatch dv)
    + sum(DSM |v_after - v_before|)
    + end_boundary_dv

Per-mission score:
    score = 2 * target_dv / (target_dv + total_dv)

The SimpleTES `combined_score` is this selected mission's score.

Your objective is to produce a valid low-delta-v trajectory for the selected
mission. Use the mission metadata to specialize the search: a Galileo-like
Jupiter mission, a Cassini-like Saturn mission, and a Voyager-like outer-planet
tour do not need the same topology or time allocation.

Good strategies may include:
- selecting flyby sequences from the allowed planets;
- using repeated Earth/Venus assists when the mission family suggests it;
- searching launch, flyby, DSM, and arrival times jointly;
- using DSMs to make hard phasing windows feasible;
- trying multi-revolution Lambert arcs when long transfer windows permit;
- keeping a lower-quality valid trajectory as a fallback.

Do not assume a fixed trajectory topology. The number, type, order, and timing
of intermediate nodes are design choices subject to max_nodes, max_GA, max_DSM,
allowed_GA_planets, and flyby altitude constraints.

Programs must be reproducible. If the search uses randomness, specify a fixed
random seed or a deterministic local random-number generator, and make repeated
runs on the same mission return the same trajectory and score.

Return the best valid trajectory found within the time limit.

The Python environment provides numpy, scipy, numba, and the bindings above.
Do this by evolving the code between # EVOLVE-BLOCK-START and # EVOLVE-BLOCK-END.
